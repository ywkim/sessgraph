# Spec: `serve` 명령

## Interface

```
sessgraph serve <file> [--port <n>]
```

- `<file>`: 필수. 세션 JSONL 파일 경로
- `--port <n>`: 선택. 기본값 `7377`. 지정 포트가 사용 중이면 다른 포트를 자동 선택하지 않고 오류로 종료한다

서버는 `127.0.0.1`에만 바인딩한다. 외부 인터페이스(`0.0.0.0` 등)로 바인딩하는 옵션을 제공하지 않는다 ([ADR-0003](../adr/ADR-0003-cli-writes-web-reads.md)).

기동 성공 시 stdout에 접속 URL 한 줄을 출력하고 포그라운드에 머무른다. `Ctrl-C`(SIGINT)로 종료한다.

종료 코드:

- `0`: 사용자가 정상 종료(SIGINT)
- `2`: 도구 오류 — 파일 없음, 인덱싱 불변식 위반, 포트 사용 중

### HTTP 엔드포인트

모두 `GET`이다. **쓰기 메서드(`POST`/`PUT`/`PATCH`/`DELETE`)는 어떤 경로에도 존재하지 않으며, 요청 시 `405`를 반환한다.**

| 경로                 | 응답                                                      |
| -------------------- | --------------------------------------------------------- |
| `/`                  | 정적 자산 (HTML/JS/CSS)                                   |
| `/api/index`         | `IndexResult` (본문 제외)                                 |
| `/api/segment/:root` | `SegmentDetail` — 해당 세그먼트의 노드 목록 (구조 필드만) |
| `/api/body?uuid=X`   | `NodeBody` — 단일 노드의 원본 JSONL 한 줄                 |

## 데이터 모델

핵심 타입은 [`inspect` 명령 Spec](20260901-1337-inspect-command.spec.md#데이터-모델)의 `IndexResult`, `Segment`, `OrphanNode`와 `src/core/types.ts`의 `NodeIndex`를 그대로 쓴다. 이 문서는 재기술하지 않는다.

`/api/index`는 `inspect --json`이 내보내는 것과 **동일한 `IndexResult`**를 그대로 응답한다. 웹 전용 변형 타입을 따로 두지 않는다 — 두 출력이 갈릴 여지를 만들지 않기 위해서다 (ADR-0001).

이 문서에서 추가로 정의하는 타입 (구현 시 `src/core/types.ts`에 추가):

```ts
interface SegmentDetail {
  readonly segment: Segment;
  /** 이 세그먼트에 속한 노드들 (root → leaf 순서). 본문은 포함하지 않는다. */
  readonly nodes: readonly NodeIndex[];
  /** 이 세그먼트의 root가 compact_boundary일 때, 화면에 표시할 재연결 명령어 */
  readonly suggestedReattachCommand: string | null;
}

interface NodeBody {
  readonly uuid: string;
  /** 원본 JSONL 한 줄 (파싱하지 않은 그대로) */
  readonly raw: string;
}
```

`buildSegmentDetail(index: IndexResult, rootUuid: string): SegmentDetail`은 `src/core`에 둔다 — 파일을 쓰지 않는 순수 계산이다. `byteOffset`으로 파일을 seek해 본문을 읽는 것은 I/O이므로 `src/cli`(서버 계층)가 수행한다.

`suggestedReattachCommand`의 `--parent` 값은 `segment.rootLogicalParentUuid`를 우선 사용하고, 그 값이 `null`이면 직전 세그먼트의 `leafUuid`로 fallback한다 — "직전 leaf" 단독 가정은 실측 두 세션 파일에서 각각 44%, 9.5% 틀렸다(ADR-0005). 어느 경로로 값을 채웠는지는 화면에 노출한다: `rootLogicalParentUuid`가 있으면 "기록된 부모", 없어서 fallback했으면 "추정값(직전 조각의 마지막 노드) — 확인 후 사용"으로 구분 표시한다. `--reason`은 사용자가 채워야 하므로 빈 자리로 둔다 (`reattach` Spec에서 필수 인자).

## 엣지 케이스 & 에러 처리

- 파일이 없음 → 서버를 기동하지 않고 종료 코드 2, "파일을 찾을 수 없습니다: {경로}"
- 인덱싱 중 불변식 위반(parentUuid 필드 전멸 등) → 서버를 기동하지 않고 종료 코드 2. 깨진 인덱스로 화면을 그리지 않는다 (ADR-0004)
- `--port`가 이미 사용 중 → 종료 코드 2, "포트 {n}이 사용 중입니다. `--port`로 다른 포트를 지정하세요". **자동으로 다른 포트를 고르지 않는다** (사용자가 어디에 접속해야 하는지 모호해진다)
- 빈 파일(0바이트) → 정상 기동. `/api/index`가 `nodeCount: 0`, 빈 세그먼트 배열을 응답하고 화면은 "표시할 기록이 없습니다"를 보여준다
- `/api/segment/:root`의 `root`가 어떤 세그먼트의 rootUuid도 아님 → `404`
- `/api/body`의 `uuid`가 인덱스에 없음 → `404`
- `/api/body`가 seek·read한 줄의 uuid가 요청한 uuid와 다름 → **서버 기동 후 원본 파일이 외부에서 변경된 경우**다. `409`와 함께 "파일이 변경되었습니다. 서버를 재시작하세요" 반환. 화면은 이 상태를 배너로 표시한다. 엉뚱한 본문을 조용히 렌더하지 않는다
- 쓰기 메서드 요청 → `405`. 읽기 전용임을 응답 본문에 명시한다
- 세그먼트의 root가 `compact_boundary`가 아닌 진짜 세션 시작점 → `suggestedReattachCommand`는 `null` (이을 대상이 아니다). 화면에서 "세션 시작점"으로 표시하며 끊김으로 표시하지 않는다
- 해소되지 않은 중복(`unresolvedDuplicates`)이 있음 → 화면 상단에 경고 영역으로 표시한다. 숨기지 않는다 (`src/web/CLAUDE.md` "표시 규칙")
- `malformedLines`가 비어있지 않음 → "N개 줄을 읽지 못함"을 화면에 표시한다

## 성능 요구사항

실측 기준선은 `inspect`와 동일한 세션 파일(829MB, 86,668줄, distinct 노드 10,726개, 세그먼트 39개)이다.

- 서버 기동(= 인덱싱 완료 후 접속 가능까지): 3초 이내 (`inspect` 인덱싱 2.5초 기준 + 서버 기동 여유, [20260901-1337-inspect-command.spec.md](20260901-1337-inspect-command.spec.md#성능-요구사항))
- 상주 메모리: 300MB 이내 (인덱스 200MB 기준 + 서버 오버헤드. 본문을 상주시키지 않는 설계)
- `/api/index` 응답: 100ms 이내 (이미 메모리에 있는 구조체 직렬화)
- 초기 화면 렌더: 세그먼트 수에만 비례하므로 파일 크기와 무관하게 1초 이내
- `/api/body` 단일 노드 응답: 50ms 이내 (단일 seek + 한 줄 read)
- 세그먼트를 펼칠 때 화면 반응: 200ms 이내. 세그먼트 내 노드가 수천 개여도 가상 스크롤로 화면에 보이는 것만 DOM에 올리므로 노드 수에 비례하지 않아야 한다

## Out of Scope

- 화면에서 기록을 직접 수정하거나 잇는 기능 (PRD Non-Goals, ADR-0003 — `reattach`의 역할)
- 여러 사용자가 동시에 접속하는 기능 (PRD Non-Goals — 인증·세션 관리를 두지 않는 이유)
- 기록 내용을 외부로 내보내거나 공유하는 기능 (PRD Non-Goals)
- 파일 변경을 감지해 인덱스를 자동 갱신하는 기능 (변경 시 `409`로 알리고 재시작을 안내할 뿐 — Design "향후 확장 고려사항")
- 본문을 제외한 구조 요약의 정적 파일 내보내기 (Design "고려한 대안" 대안1 — 별도 PRD 대상)
- 여러 세션 파일을 한 화면에서 비교하는 기능 — 화면 비교뿐 아니라, 여러 파일을 하나로 병합해 인덱싱하는 것 자체도 범위 밖이다 (`inspect` Spec Out of Scope와 동일 이유)
