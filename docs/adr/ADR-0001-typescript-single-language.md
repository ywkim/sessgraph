# ADR-0001: 인덱서·CLI·웹을 단일 언어(TypeScript)로 구현한다

## Status

Accepted

## Context

이 도구는 두 실행 형태를 갖는다 — 수술과 진단을 수행하는 CLI, 그리고 세션 구조를 보여주는 로컬 웹 뷰어. 자연스러운 초기 구성은 "인덱싱이 빠른 Python 백엔드 + 웹 UI를 위한 TypeScript 프론트엔드"였다.

그러나 이 도구가 파싱하는 Claude Code 세션 JSONL의 필드(`uuid`, `parentUuid`, `type`, `subtype`, `compact_boundary`)는 [공식 문서가 "internal, changes between versions"로 명시](https://code.claude.com/docs/en/sessions.md)한 비공개 스키마다. 즉 **스키마 변경은 가정이 아니라 확정된 미래**다.

두 언어로 타입을 각각 정의하면 스키마가 바뀔 때 한쪽만 고쳐지고 다른 쪽이 조용히 어긋난다. 특히 위험한 실패 모드는 필드명이 바뀌어 `parentUuid`가 전부 `undefined`가 되고, 도구가 "끊긴 곳 없음, 정상"이라고 **틀린 답을 자신 있게 보고**하는 것이다.

## 후보 기술 & 각 선택지

**후보1: Python 인덱서 + TypeScript 웹 (2언어)**

- 장점: 인덱싱이 근소하게 빠름. Python 표준 라이브러리만으로 프로토타입 가능
- 단점: 스키마를 두 곳에 정의. 웹 화면과 CLI 리포트가 서로 다른 답을 낼 수 있음
- 실측: 829MB / 86,668줄 세션 인덱싱 **1.70초**

**후보2: TypeScript 단일 (Node)**

- 장점: 스키마 정의 1곳. CLI와 웹이 **같은 인덱서 함수**를 호출하므로 타입 공유보다 강한 보장
- 단점: 인덱싱이 근소하게 느림
- 실측: 동일 파일 **2.14초**, 힙 95MB

**후보3: Rust 단일**

- 장점: 최고 성능
- 단점: 웹 UI를 위해 결국 WASM 또는 별도 JS 레이어가 필요해 2언어 문제가 되돌아옴. 이 규모에서 성능 이득이 무의미

## Decision

인덱서·CLI·웹 뷰어를 모두 TypeScript로 구현하고, 파싱·그래프 구축 로직은 `src/core/`에 단 하나만 둔다.

## Rationale (선택 이유)

0.44초 차이는 이 도구의 사용 경험에서 무의미하다. 인덱싱은 실행당 1회이고 이후 질의는 메모리에서 이뤄진다. 반면 스키마 정의가 두 벌이 되는 비용은 스키마가 바뀔 때마다 반복되고, 그 실패가 **조용하다**.

성능이 실제 제약이었다면 판단이 달랐겠지만, 실측 결과 829MB 파일에서도 2.14초·95MB로 단일 언어 선택의 대가가 사실상 없다. 성능을 근거로 복잡도를 사는 거래가 성립하지 않는다.

핵심은 타입 공유가 아니라 **로직 공유**다. 타입만 공유해도 두 구현이 서로 다른 정책(예: 중복 레코드 처리 순서)을 쓰면 답이 갈린다 — 이 실패는 [ADR-0004](ADR-0004-schema-drift-defense.md)에서 실제로 관측했다.

## Consequences

### 장점

- 스키마 정의가 1곳. 변경 시 컴파일러가 모든 사용처를 잡아준다
- `sessgraph inspect`(CLI)와 `sessgraph serve`(웹)가 동일 함수를 호출하므로 두 출력이 어긋날 수 없다
- 배포·테스트 툴체인이 하나

### 단점 & 트레이드오프

- Python 대비 인덱싱 0.44초 손해
- Node 런타임 의존. 다만 이 도구의 사용자는 Claude Code 사용자이므로 Node는 이미 있다고 가정할 수 있다

### 향후 기능이 따를 원칙

- 파싱·그래프 구축 로직은 `src/core/`에만 둔다. `src/cli/`나 `src/web/`이 JSONL을 직접 파싱하지 않는다
- 새 언어를 도입하지 않는다. 성능 문제가 생기면 먼저 알고리즘·자료구조를 바꾼다

## 언제 이 결정을 다시 검토할 것인가?

- 단일 세션 파일이 5GB를 넘거나 인덱싱이 30초를 넘을 때
- 인덱스를 여러 세션에 걸쳐 영속 캐시해야 해서 별도 저장 계층이 필요해질 때
