# PRD: 조각 내부에서 갈라진 갱신/재실행 눈으로 보기

## Why (목표)

조각 화면은 root→leaf를 DFS로 한 줄로 펴서 lineNo 순으로 보여준다([`buildSegmentDetail`](../../src/core/serve.ts)). 그런데 파일 안의 부모-자식 관계는 실제로는 트리다 — 한 부모가 자식을 여럿 가질 수 있다. 지금 화면은 이 분기를 감추고 한 줄로 이어 붙이므로, **서로 다른 갈래에서 나온 두 항목이 마치 연속된 하나의 흐름처럼 보인다.**

1,633개 세션을 실측한 결과, 기록을 중복 제거한 후에도 자식이 둘 이상인 부모가 32,935개 있었고, 이 중 자식 쪽에 도구 결과가 아닌 **사용자 메시지가 둘 이상**인 경우(재실행·수정으로 갈라진 진짜 분기)가 5,696개, 세션 464개(28.4%)에서 나타났다. 예:

```
L4  user  (모델 변경 안내)
 ├ L6  02:00:54 "참고: ~/docs (CLAUDE.local.md 포함)"
 └ L10 02:01:15 "설명해 주세요: ~/docs (CLAUDE.local.md 포함)"
```

같은 부모에서 21초 간격으로 문구만 바꾼 두 갈래가 나왔는데, 지금 화면은 이 둘을 이어진 대화처럼 보여준다. 어느 쪽이 최종 채택된 갈래인지, 폐기된 쪽이 있는지 알 방법이 없다.

나머지 27,239개는 한 모델 응답이 여러 도구 호출을 담아 그 결과가 같은 부모에 붙는 구조적 산물이다 — 사용자가 볼 이유가 없는 노이즈다. 이 둘을 구분하지 않고 표시하면 27,239 대 5,696으로 진짜 신호가 묻힌다.

## What / Success Criteria (요구사항 & 성공 기준)

- 한 부모에서 **사용자 메시지가 둘 이상** 갈라져 나온 지점(재실행/수정)을 조각 화면에서 식별할 수 있다
- 도구 병렬 호출로 생긴 분기(자식이 전부 tool_use/tool_result인 경우)는 이 표시 대상에서 제외한다 — 노이즈가 신호를 덮지 않는다
- 갈라진 갈래 중 어느 것이 세그먼트의 채택된 경로(현재 DFS가 따라가는 경로)이고 어느 것이 곁가지인지 화면에서 구분된다
- 곁가지도 목록에서 조용히 사라지지 않는다 — 존재는 표시하되, 펼치는 것은 이번 범위 밖일 수 있다
- 곁가지가 **어느 분기점 소속인지**(레인 색), **몇 겹 중첩됐는지**(레인 개수), **시작·끝이 어디인지**(레인의 반쪽선 경계)를 화면에서 구분할 수 있다 — 2026-09-07 재피드백으로 추가된 기준
- 성공 기준: 재실행/수정으로 갈라진 지점이 있는 조각을 열었을 때, 사용자가 "이 두 메시지가 왜 이어져 보이는지"뿐 아니라 "이 갈래가 어디서 시작해서 어디서 끝나는지"도 화면만 보고 설명할 수 있다

## Non-Goals (명시적 범위 제외)

- **세그먼트 사이의 출처(어느 조각이 어디서 이어져 오는가)** — 이건 [조각 출처 백링크](20260906-2000-segment-origin-backlink.prd.md)가 이미 다루는 별개 범위다. 이 PRD는 **한 세그먼트 안**에서 벌어지는 분기만 다룬다
- 도구 병렬 호출로 생긴 분기를 시각화하는 것 — Why에서 확인했듯 노이즈다. 필터링 대상이지 표시 대상이 아니다
- 곁가지를 펼쳐서 그 내용을 보여주는 것 — 이번 범위는 "분기가 있다는 사실과 위치"를 드러내는 것까지다. 곁가지 내용 탐색은 필요성이 확인되면 별도로 다룬다
- force-directed 등 별도 그래프 엔진을 도입해 화면 배치 자체를 재설계하는 것 — 세로 타임라인 고정 배치, 그리고 가상 스크롤을 지탱하는 고정 행 높이(`--row-height`)는 그대로 둔다 (조각 출처 백링크 Design "대안4·5"와 같은 판단). 단, 이 고정 틀 **안에서** `git log --graph`처럼 레인(컬럼)을 그려 분기점 소속·중첩·범위를 표시하는 것은 범위에 포함한다 — 배지만으로는 갈래 자체가 안 보인다는 피드백(2026-09-07)에 이어, 테두리색만으로도 구조(어느 분기점 소속인지/깊이/시작-끝 범위)가 안 보인다는 재피드백(2026-09-07)으로 범위를 다시 넓혔다. 레인 폭은 실측한 "동시 open 브랜치 수"(중앙값 3, p90 10, p99 21) 기준 상한을 두어(현재 구현 5) 무한정 넓어지지 않게 한다
- 채택 경로를 고르는 새 규칙을 만드는 것 — 지금 DFS가 마지막에 push된 자식을 따라가는 순서를 그대로 "채택 경로"로 삼는다. 더 나은 채택 기준이 필요한지는 확인되지 않았다
