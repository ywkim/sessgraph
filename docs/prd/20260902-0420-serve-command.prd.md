# PRD: 기록 구조를 눈으로 보기

## Why (목표)

끊긴 지점을 확인하는 기능은 글로 된 목록을 보여준다. 하지만 기록이 길고 끊긴 지점이 여러 개일 때, 사용자는 전체 그림 — 어디서부터 어디까지가 하나로 이어져 있고, 어디가 몇 번이나 끊겼는지 — 을 한눈에 파악하고 싶어한다.

특히 어느 지점을 이을지 결정하려면, 목록만으로는 판단하기 어렵다. 시간 순서와 조각 크기를 눈으로 비교하면서, 이을 지점을 고르는 편이 훨씬 자연스럽다.

## What / Success Criteria (요구사항 & 성공 기준)

- 사용자가 자신의 기록 전체를, 조각별로 나뉜 시간순 그림으로 볼 수 있다
- 조각 하나를 펼치면, 그 안의 실제 대화 내용을 확인할 수 있다
- 끊긴 지점을 발견하면, 그 지점을 잇는 데 필요한 다음 조치(명령)를 바로 확인할 수 있다 — 다만 그 조치를 실제로 실행하는 것은 이 화면이 아니라 다른 곳에서 한다
- 이 화면에서 보여주는 내용은, 지점을 확인하는 기능이 보여주는 내용과 항상 같아야 한다 — 같은 기록을 봤는데 두 곳에서 다른 답이 나오면 안 된다
- 사용자가 손에 든 작은 화면으로도 같은 내용을 읽을 수 있다 — 자리에 앉아 큰 화면을 볼 때만 쓸 수 있는 기능이 아니다
- 성공 기준: 매우 큰 기록이라도, 전체 그림을 보기까지 오래 기다리지 않아야 한다. 조각을 하나씩 펼쳐볼 때도 그때그때 즉시 반응해야 한다
- 성공 기준: 화면이 좁아져도 글자가 서로 겹치거나 가려지지 않는다. 좁은 화면에서 일부 내용을 줄여 보여주더라도, 무엇이 줄어든 것인지 사용자가 알 수 있어야 하고 전체 값을 확인할 방법이 있어야 한다
- 성공 기준: 화면에 표시된 시각을 보고, 사용자가 자신이 그 일을 겪은 시점과 맞는지 바로 알 수 있어야 한다 — 실제로는 다른 시간대의 시각인데 자신의 시간대라고 착각하게 만들면 안 된다
- 사용자가 자기 기록 여러 벌을 한 화면에서 오가며 볼 수 있다 — 다른 기록을 보려고 화면을 껐다가 다시 띄우지 않아도 된다
- 성공 기준: 여러 벌을 열어두더라도, 처음 화면이 뜨기까지 기다리는 시간이 기록 수에 비례해 길어지지 않는다
- 성공 기준: 그중 한 벌을 읽지 못하더라도 나머지는 볼 수 있어야 한다. 다만 읽지 못한 것이 무엇이고 왜인지가 화면에 드러나야 한다 — 목록에서 조용히 빠뜨려 사용자가 그 기록의 존재 자체를 모르게 만들면 안 된다

## Non-Goals (명시적 범위 제외)

- 이 화면에서 기록을 직접 수정하거나 잇는 기능은 포함하지 않는다 (보여주기만 한다 — 실제 변경은 별도 기능의 역할이다)
- 여러 사용자가 동시에 같은 화면에 접속해 보는 기능은 포함하지 않는다 (혼자 보는 용도다). 이는 **보는 사람이 여럿인 경우**를 제외하는 것이며, 혼자서 자기 기록 여러 벌을 보는 것은 위 요구사항에 포함된다 — 두 가지는 다른 이야기다
- 기록 내용을 외부로 내보내거나 공유하는 기능은 포함하지 않는다

## 콘텐츠 필터링 정책

이 섹션은 "기록 전체"라는 용어의 범위와, 펼친 세션 화면에서 사용자에게 노출하는 노드의 기준을 정의한다.

### 정의: "기록 전체"에 포함되는 노드

사용자가 한 대화의 흐름은:
- **포함:** `role: "user"` (사용자 입력), `role: "assistant" | "claude"` (AI 응답)
- **제외:** 도구 호출·결과 (`tool_use`, `tool_result`) 및 구조적 산물

도구 호출과 결과를 제외하는 이유:

1. **구조적 노이즈:** 실측 기준 자식이 둘 이상인 부모 32,935개 중 27,239개(82.7%)는 도구 병렬 호출로 생긴 분기였고, 사용자 재실행/수정은 5,696개(17.3%)뿐이었다 ([segment-branch-view PRD](20260906-1400-segment-branch-view.prd.md))
2. **사용자 가치:** 이 도구의 주 목표는 "어디서 기록이 끊겼는가"를 판단하는 것이고, 도구 호출 분기는 세션 컴팩트 정책의 부산물일 뿐 대화 연속성과 무관하다
3. **좁은 화면:** 도구 호출 분기를 제외하면 좁은 화면에서도 사용자 대화 흐름을 명확히 따를 수 있다 ([responsive-layout Design](../design/20260904-1130-responsive-layout.tdd.md))

다만 도구 호출 분기의 **존재**는 숨기지 않는다 — segment-branch-view의 "곁가지 N개" 배지로 언제든 확인할 수 있어야 한다.

### 노드 렌더링 필터링 정책 (화면 너비별)

#### Wide 화면 (> 768px)
- 위 "포함되는 노드" 조건을 만족하는 모든 노드를 표시한다
- 도구 호출은 표시하지 않는다

#### Narrow 화면 (≤ 768px)
- 위 "포함되는 노드" 조건을 만족하는 모든 노드를 표시한다 (wide와 동일)
- 축약되는 것은 **콘텐츠**이지 노드 자체가 아니다 (uuid truncate, body line limit)
- 축약된 콘텐츠마다 "전체 보기" 수단이 있어야 한다:
  - uuid: 클릭/복사 버튼
  - body: dialog 클릭
  - 세션 경로: 호버 또는 항상 표시

### 세션 목록 화면 (Session List)

#### 각 세션 항목의 표시 정보

- **세션 ID:** sha256(경로) 앞 12자 (항상 표시, 조회 키)
- **세션 경로:**
  - wide: 절대 경로 (또는 사용자 입력 경로)
  - narrow: basename, 또는 상대 경로
  - 클릭/호버로 전체 경로 확인 가능해야 함
- **상태 표시:**
  - loading: ⏳ 로딩 중
  - ready: ✓ 표시 가능
  - failed: ✗ 아이콘 + 오류 메시지 (한 줄, 말줄임)
- **메타 정보 (선택):**
  - 노드 수 (용량 감각)
  - 첫 메시지 타임스탬프 (언제 세션이 시작됐는가)

#### 목록의 기본 정렬

**첫 메시지 시간순, 최근부터 오래된 순서** (내림차순)

사유:
- 사용자 관점에서 "최근에 작업한 세션이 위에"가 가장 유용함
- 여러 세션 중 목표 세션을 빠르게 찾을 수 있음

#### 좁은 화면에서의 표시

- 세션 경로: basename만 표시, 전체 경로는 호버/클릭 시 표시
- 메타 정보: 생략 (노드 수, 타임스탬프)
- 상태 아이콘: 텍스트 생략, 아이콘만 표시
- 대량 세션 처리: 스크롤 시 지연 로드 ([multi-session-serve Design](../design/20260905-0641-multi-session-serve.tdd.md) 참고)

#### 검색 & 필터링

**지원 기능:**
- 세션 이름/경로로 검색 가능 (파일명 기준, 디렉터리명 포함)
- 필터링은 미정 (first-phase non-goal)

**위치:** 검색창은 목록 상단에 고정
