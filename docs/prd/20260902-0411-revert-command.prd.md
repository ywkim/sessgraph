# PRD: 잇기 작업을 되돌리기

## Why (목표)

끊긴 대화 조각을 이었는데, 그 결과가 기대와 다르거나 잘못된 지점을 이었다는 걸 나중에 알게 될 수 있다. 이럴 때 사용자는 원래 상태로 돌아갈 방법이 있어야 안심하고 잇기 작업을 시도할 수 있다.

되돌릴 방법이 없다면, 사용자는 잇기 작업 자체를 시도하기 꺼리게 된다. 특히 이 기록은 다시 만들 수 없는 개인적인 대화 기록이므로, 실수했을 때 되돌릴 수 있다는 확신이 잇기 기능 전체를 실제로 쓸 수 있게 만드는 전제조건이다.

## What / Success Criteria (요구사항 & 성공 기준)

- 사용자가 잇기 작업을 한 기록을, 그 작업을 하기 직전 상태로 되돌릴 수 있다
- 되돌리기 전에 무엇이 되돌려질지 미리 확인할 수 있다
- 여러 번 잇기 작업을 했다면, 가장 최근 작업만 되돌릴지 혹은 특정 시점까지 되돌릴지 선택할 수 있다
- 되돌린 뒤에는, 정말로 원래 상태로 돌아갔는지 확인할 수 있다 (연결 상태 확인 기능을 그대로 이용)
- 성공 기준: 되돌리기는 원본을 훼손하지 않는 방식으로 이뤄져야 하며, 되돌린 결과는 잇기 작업을 하기 전과 완전히 동일해야 한다

## Non-Goals (명시적 범위 제외)

- 잇기 작업 일부만 골라서 취소하는 기능(예: 여러 지점을 이었는데 그중 하나만 되돌리기)은 포함하지 않는다 — 한 번의 되돌리기는 그 작업 전체 단위로 이뤄진다
- 되돌린 뒤 다시 잇기를 자동으로 재시도하는 기능은 포함하지 않는다
- 기록을 만든 적 없는 지점으로 임의로 되돌리는 기능은 포함하지 않는다 (실제로 보관된 이전 상태로만 되돌릴 수 있다)
