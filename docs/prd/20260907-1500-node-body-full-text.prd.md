# PRD: 노드 본문 미리보기 전체 보기

## Why (목표)

[좁은 화면 레이아웃 설계](../design/20260904-1130-responsive-layout.tdd.md)는 행 높이를 일정하게 지키기 위해 대화 내용 미리보기를 정해진 줄 수로 자른다. 이때 "줄인 표시임을 시각적으로 드러내고, 전체 값은 별도 수단으로 도달 가능하게 한다"는 조건을 [기존 PRD 성공 기준](20260902-0420-serve-command.prd.md#what--success-criteria-요구사항--성공-기준)에 이미 명시했다.

실측 결과 이 조건이 지켜지지 않는 사례를 확인했다: 미리보기가 정해진 줄 수를 살짝 넘는 항목(예: `"두 태스크 모두 해당 프로젝트에서 제거"`)은 마지막 몇 글자("제거")가 화면 어디서도 보이지 않는다. 저장된 원본 내용은 그대로 남아 있지만, 사용자가 그것을 볼 방법이 화면에 전혀 없다.

즉 이것은 새 기능 요청이 아니라, 이미 확정된 성공 기준이 구현에서 누락된 결함이다.

## What / Success Criteria (요구사항 & 성공 기준)

- 대화 내용 미리보기가 잘려 있을 때, 사용자가 잘렸다는 사실을 화면에서 알 수 있다
- 사용자가 원하면 그 항목의 전체 내용을 확인할 수 있다
- 성공 기준: 전체 내용을 확인하는 동작이 그 행의 높이를 바꾸지 않는다 — [행 높이 불변 설계](../design/20260904-1130-responsive-layout.tdd.md#아키텍처-how)가 목록을 매끄럽게 스크롤하기 위해 지키는 전제를 깨지 않는다
- 성공 기준: 좁은 화면(모바일)에서도 동일하게 전체 내용에 도달할 수 있다 — 마우스로만 가능한 수단만으로 해결하지 않는다

## Non-Goals (명시적 범위 제외)

- 대화 내용을 그 자리에서 수정하는 기능은 포함하지 않는다 (보기 전용)
- 미리보기 자체의 줄 수·글자 크기를 바꾸는 것은 범위 밖이다 — 이 PRD는 "잘린 나머지를 볼 방법"만 다룬다
- 검색 결과 하이라이트 등 다른 화면의 내용 표시 방식은 범위 밖이다 (조각을 펼친 목록 화면만 다룬다)

## 참고 자료

- 실측: 서로 다른 두 기록에서 재현 — 특정 기록 하나에 국한된 문제가 아니다
- 관련 기존 설계: [좁은 화면 레이아웃](../design/20260904-1130-responsive-layout.tdd.md) "행 높이 불변" 절 — "줄여서 보여준 값은 사용자가 전체를 확인할 방법이 있어야 한다"고 이미 명시했으나 대화 내용 미리보기에는 구현되지 않았다. 식별자(uuid) 표시는 가로로 밀어보는 방식으로 이미 이 조건을 충족하고 있어, 내용 미리보기에도 상응하는 수단이 필요하다
