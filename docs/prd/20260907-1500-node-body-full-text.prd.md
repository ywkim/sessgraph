# PRD: 노드 본문 미리보기 전체 보기

## Why (목표)

[좁은 화면 레이아웃 설계](../design/20260904-1130-responsive-layout.tdd.md)는 행 높이를 상수로 지키기 위해 노드 본문 미리보기를 고정 줄 수(2.6em)로 자른다. 이때 "줄인 표시임을 시각적으로 드러내고, 전체 값은 별도 수단으로 도달 가능하게 한다"는 조건을 [기존 PRD 성공 기준](20260902-0420-serve-command.prd.md#what--success-criteria-요구사항--성공-기준)에 이미 명시했다.

실측 결과 이 조건이 지켜지지 않는 사례를 확인했다: 미리보기가 2줄을 살짝 넘는 노드(예: `"두 태스크 모두 해당 프로젝트에서 제거"`)는 마지막 몇 글자("제거")가 화면 어디서도 보이지 않는다. `.node-body`에는 클릭이나 다른 방법으로 전체 텍스트에 도달하는 경로가 없다 — DOM(`textContent`)에는 값이 남아있지만 사용자가 그것을 볼 방법이 없다.

즉 이것은 새 기능 요청이 아니라, 이미 확정된 성공 기준이 구현에서 누락된 결함이다.

## What / Success Criteria (요구사항 & 성공 기준)

- 노드 본문 미리보기가 잘려 있을 때, 사용자가 잘렸다는 사실을 화면에서 알 수 있다
- 사용자가 원하면 그 노드의 전체 본문 텍스트를 확인할 수 있다
- 성공 기준: 전체 텍스트를 확인하는 동작이 그 행의 높이를 바꾸지 않는다 — [행 높이 불변 설계](../design/20260904-1130-responsive-layout.tdd.md#아키텍처-how)가 가상 스크롤 위치 계산의 전제로 삼는 `ROW_HEIGHT` 상수를 깨지 않는다
- 성공 기준: 좁은 화면(모바일)에서도 동일하게 전체 텍스트에 도달할 수 있다 — 마우스 hover 전용 수단만으로 해결하지 않는다

## Non-Goals (명시적 범위 제외)

- 노드 본문을 그 자리에서 수정하는 기능은 포함하지 않는다 (보기 전용)
- 미리보기 자체의 줄 수·글자 크기를 바꾸는 것은 범위 밖이다 — 이 PRD는 "잘린 나머지를 볼 방법"만 다룬다
- 검색 결과 하이라이트 등 다른 화면의 본문 표시 방식은 범위 밖이다 (세그먼트 펼침 목록의 `.node-body`만 다룬다)

## 참고 자료

- 실측: 세션 `50cdc7f33dab`(세그먼트 `90a28f46-...`)와 세션 `40b28bdf2698`(세그먼트 `be64bc95-8f7c-4eb7-ad31-db17f26586ba`) 양쪽에서 재현 — 특정 세션에 국한된 문제가 아니다
- 관련 기존 설계: [좁은 화면 레이아웃](../design/20260904-1130-responsive-layout.tdd.md) "행 높이 불변" 절 — "줄여서 보여준 값은 사용자가 전체를 확인할 방법이 있어야 한다"고 이미 명시했으나 `.node-body`에는 구현되지 않았다. uuid는 `overflow-x: auto`로 이미 이 조건을 충족하고 있어(가로 스크롤로 전체 값 도달 가능), 본문에도 상응하는 수단이 필요하다
